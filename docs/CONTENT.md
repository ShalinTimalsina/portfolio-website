## Tone of Voice

| Attribute | Description |
|-----------|-------------|
| **Confident, not arrogant** | State what you've built, not how great you are |
| **Technical, not jargon-heavy** | A senior engineer should understand it; a designer shouldn't be lost |
| **Concise** | Every sentence earns its place. No filler paragraphs |
| **First person** | "I built" not "Shalin built" or "We delivered" |
| **Active voice** | "I deployed a 3-tier AWS architecture" not "A 3-tier architecture was deployed" |

## Copy Rules

1. **No filler intros.** Don't start sections with "Welcome to my portfolio" or "I'm passionate about…"
2. **Lead with the work.** Project descriptions start with what it does, then the stack, then the outcome.
3. **Numbers are real or absent.** Never fabricate metrics. If you can't measure it, describe the impact qualitatively.
4. **Labels are honest.** Skills use the Daily / Working / Learning tiers (see below).
5. **CTAs are specific.** "Read the case study" not "Learn more". "Send me an email" not "Get in touch".

## Banned Phrases

| Phrase | Why | Replace With |
|--------|-----|-------------|
| "Passionate about technology" | Empty, overused | Delete entirely or be specific |
| "Results-driven" | Corporate filler | Show the result instead |
| "Leveraging cutting-edge" | Buzzword soup | Name the specific tool |
| "Full-stack wizard/ninja/guru" | Cringe | "Cloud & DevOps engineer" |
| "Solutions for modern businesses" | Means nothing | Delete |
| "Let's connect!" | LinkedIn energy | "Email me at…" or specific CTA |
| "Proven track record" | Unverifiable | Link to the actual project |
